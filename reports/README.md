# Assessment artifacts — what each one is, and what stands behind it

Two kinds of artifact live here, produced differently and carrying different
assurance. An audit found that the file labelled "Authoritative" across the
repository was the one with the least verification behind it, so each is
described here by how it is actually produced.

## Machine-generated, CI-verified

Written by `python3 test_real_world.py` from `official_documents.py` and
`sample_documents.py`. Deterministic — regenerating produces byte-identical
output. Each carries a **corpus fingerprint** (which texts were assessed) and
the export carries a **toolchain fingerprint** (which code assessed them). CI
fails if the committed copies differ from regenerated output, and fails again if
two consecutive runs disagree.

| File | Audience | Contents |
|---|---|---|
| `laif_real_world_assessment.md` | Reviewers, document owners | Full assessment: plain-language reading, evidence locator, placement guidance, attachment points, peer exemplars, scorecards, remediation |
| `laif_executive_summary.md` | Executives, boards, ministers | One page: the finding, corpus at a glance, highest-value actions, how to read it |
| `laif_assessment_data.json` | GRC tooling, dashboards, re-analysis | Schema `laif.assessment.v1` r4 — verdicts, scores, calibration, functional alignment, gaps, remediation, language coverage, toolchain fingerprint |

**These are the artifacts to cite.** Any finding in them can be traced to the
exact text and the exact code that produced it.

## Narrative analyses — historical, not regenerated

Authored analyses, not outputs of the toolchain. They are retained because the
verified corpus manifest cites them as the assessment reference for the four
pinned instruments, and because they record reasoning the deterministic pipeline
does not produce.

| File | Produced | Model | Status |
|---|---|---|---|
| `laif_full_assessment.md` | 5 May 2026 | Refined Model v1.1 | Historical. Not regenerated, not fingerprinted, not CI-verified. |
| `laif_assessment_aus_ai_policy_v2.md` | 11 May 2026 | Refined Model v1.1 | Historical. Source content from web research — see its own provenance notice. |

**What that means in practice.** Detection, scoring, and report wording have all
changed substantially since May 2026, so these files do not reflect what the
current engine produces and the two cannot be reconciled by inspection. Cite
them as the reasoning recorded at that date, under that model version — not as
current findings, and not as reproducible output. Where a current, verifiable
assessment of the same instruments is needed, it is in
`laif_real_world_assessment.md`.

## Adding an artifact here

Every file in this directory must be one of the two kinds above:

- generated by the deterministic pipeline, in which case add it to
  `test_real_world.py` so CI regenerates and checks it; or
- a narrative analysis, in which case add a row to the table above with its
  production date and model version.

`tests/test_governance.py` fails if a file appears in `reports/` that is neither.
